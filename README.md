## Parallel Core RKNN: Demo of Real‑Time YOLO Inference on Radxa ROCK 5B/5B+
Демонстрационный проект для запуска детекции объектов (YOLO) в режиме реального времени на Radxa ROCK 5B / 5B+ с использованием RKNN и параллельных потоков.

Цель проекта — показать, как организовать параллельный логический вывод (inference) на Rockchip RK3588, чтобы увеличить пропускную способность (FPS) при сохранении низкой задержки на один кадр. Подходит как стартовая база для собственных проектов.

**Что делает этот код**
Запускает несколько рабочих потоков (workers), каждый со своей копией RKNN‑модели.
Распределяет кадры между потоками: каждый поток обрабатывает свой кадр независимо.
Демонстрирует схему «1 поток → 1 модель → 1 кадр в момент времени» (модель не может обрабатывать несколько кадров одновременно).
Показывает базовый пайплайн: захват кадра → инференс → вывод результатов.
Это именно демонстрация архитектуры: можно менять количество потоков, входные размеры, тип модели и смотреть, как меняется FPS и загрузка CPU/NPU.

## Архитектура и идея
Основная идея вдохновлена примером из . Вместо последовательного инференса используется пул рабочих потоков:

Инициализируется N потоков (например, 4).
В каждом потоке загружается своя копия .rknn модели.
Кадры распределяются по потокам (в демо — по очереди).
Каждый поток делает инференс независимо.
Результаты собираются и могут быть отображены или переданы дальше (трекер, управление, лог и т.п.).
Такой подход позволяет масштабировать пропускную способность почти линейно с числом потоков — до тех пор, пока хватает ресурсов NPU/CPU.

Важно: Это демонстрационный код. Для продакшена потребуется добавить обработку ошибок, контроль очередей, таймауты, более гибкое распределение нагрузки и мониторинг.

## Требования и окружение

**На хост‑машине (x86/x64, для конвертации моделей)**

Python 3.8+
rknn-toolkit2 для конвертации и профилирования моделей
Доступ к инструментам конвертации (ONNX/PyTorch → RKNN)

**На Radxa ROCK 5B/5B+ (целевая плата)**

ОС Linux (рекомендуется Debian/Ubuntu для ARM)
Установленный RKNN runtime и драйверы NPU
Python 3.8+ и зависимости проекта
Установка окружения (rknn‑toolkit2)
***Вариант A***: Установка rknn‑toolkit2 на хост (для конвертации моделей)
На компьютере разработчика (не на Radxa):

pip install rknn-toolkit2

rknn-toolkit2 используется для конвертации, квантования и профилирования модели. Полученный .rknn файл затем копируется на Radxa для запуска.

***Вариант B***: Проверка RKNN runtime на Radxa

На плате Radxa проверьте доступность RKNN API:

python3 -c "import rknn.api as api; print(api.__version__)"
Если импорт не проходит — убедитесь, что установлены пакеты RKNN runtime для вашего образа ОС. В официальных образах Radxa они часто уже присутствуют либо доступны в репозиториях Radxa.

**Зависимости проекта**

Типичные зависимости: opencv-python, numpy и тд, устанавливается автоматически с установкой toolkit2. Если у вас есть дополнительные компоненты (трекеры, SDK камер и т.д.)

**Быстрый старт**

Конвертируйте модель YOLO в формат .rknn с помощью rknn-toolkit2.

Скопируйте полученный .rknn файл на Radxa (например, через rsync или scp).

Настройте количество рабочих потоков (по умолчанию 4, можно менять через аргументы командной строки).

Запустите пайплайн детекции:

python3 detect_demo_rknn.py

Наблюдайте за FPS и загрузкой CPU/NPU, при необходимости корректируйте число потоков.

Рекомендации по производительности
Начинайте с 2–4 потоков и замеряйте FPS: увеличение числа потоков не всегда даёт прирост из‑за ограничений NPU и конкуренции за память.
Используйте фиксированный размер входа (input resolution) — это снижает накладные расходы.
Выносите тяжёлые операции (запись логов, сохранение кадров, отрисовку) из критического пути инференса.
Профилируйте модель в rknn-toolkit2, чтобы убедиться, что она оптимально использует NPU.
